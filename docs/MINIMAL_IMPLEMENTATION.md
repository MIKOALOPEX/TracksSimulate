# 0.4.0-prototype：负重轮悬挂与基础承载

> 此文保留 0.4.0 的装配与悬挂说明。当前 0.5.0 已接入带面承载、驱动与自由滚动，新增操作和统一测试请以 [物理测试说明](PHYSICS_MILESTONE.md) 为准。

2026-10-01。用户已验证 0.2.2 的呈现基本满足要求。本轮新增负重轮原生碰撞体、悬挂、参数面板和动态轮心绕带；未启动 Minecraft。编译、几何/参数检查和独立原生物理检查已通过，游戏内装配、界面与卸载仍待手动验证。本轮新增负重轮缩放、三向偏移、隐藏与整组配置，见 [参数与验收说明](WHEEL_PARAMETERS.md)。

## 如何测试

1. 双击 `D:\CreateAdd\Start_TracksSimulate_Client.bat`。原脚本继续先在线准备，失败则离线重试；它会编译当前源码，不需要把产物 JAR 放入 mods。
2. 建议新建创造世界。在“履带模拟 · 原型”创造物品栏取得导轮、负重轮、托带轮，另取 Create 传动杆、传送带、扳手和动力源。
3. 三种轮子均可直接放在方块表面，轮轴垂直于点击面，不需要预放 shaft；也保留右键未浸水 Create shaft 原位转换并继承轴向的方式。
4. 手持 Create 传送带，按希望的顺序逐个右键轮子，最后再次右键第一个轮子闭合。显示 Create 同色号的黄色轮体包围框，履带轮廓无交叉为绿色、有交叉为红色；线宽统一，不再绘制轮心连线或侧向小框；潜行右键传送带撤销最后一个点。点击轮面中心区域表示自动绕行；点击上/下/左/右边缘提供相应绕行侧提示；无交叉优先，必要时会调整包覆侧。左右按轮轴平面判断，不随观察者朝向变化。创建一环消耗一个传送带（创造模式不消耗）。
未闭合的选择只存在于当前玩家会话中，不再写入传送带物品或存档。切换快捷栏、主副手交换、丢弃物品、打开界面、右键空气或其它方块、死亡、离线/换维度都会取消；换回传送带不会恢复旧选择。闭合后的履带仍正常保存。

5. 向导轮轴端接入 Create 动力。该环轮子和带面随之转动；反转源转速会反向显示。没有导轮也允许闭环，但本轮尚不计算被外力拖动后的自由滚动。
6. 潜行使用扳手点击任意轮子的原安装点，打开尺寸/偏移、显示/轴和履带设置，负重轮另有悬挂页。导轮全轴/半轴在“显示/轴”页保存；半轴状态下普通扳手点击轴端选择连接侧。
7. 无正在进行的点选时，潜行使用传送带点击已连接轮组，拆除整个环并保留轮子。生存模式退还一个传送带，要求整环已加载且可编辑。直接挖掉轮子会让剩余环失效，不退还带子。
8. 保存退出后再进入，检查轮组顺序、连接和显示恢复。

可用指令取物：

```mcfunction
/give @s trackssimulate:drive_wheel
/give @s trackssimulate:road_wheel
/give @s trackssimulate:return_wheel
```

## 推荐首个布置

在同一 X 平面的侧视图放三个轴向 X 的轮子。例如安装点分别为 `(0, 4, 0)`、`(0, 4, 4)`、`(0, 7, 2)`，按这个顺序选中，再点首轮闭合。两个下轮至少一个用导轮，顶轮可以用托带轮。也可先用两个相距 4 格的导轮/负重轮验证最简单的环。

不自动排序或改为凸包。仍要求同一车体/静态世界中的同平面轮组，但每个轮子可独立正向/反向包覆，允许从下方或左右经过。轮体重叠和包围线交叉不直接拒绝，也不会静默删除内侧轮；每次添加或撤销选点都重算完整闭环，先尝试保持顺序并消除交叉，仍有交叉时预览变红。放置交叉履带时显示红色状态栏及聊天提示，不阻止玩家承担该布置的后果。对于包含/同心等不存在正常公切线的退化连接使用确定的直线过渡，可能穿轮，不声称它是物理上有效的接触。完全没有长度的闭环仍不提交。上限为 32 轮、相邻跨度 32 格、总长 128 格、2048 个显示段。

## 本轮已实现

- 三款用户模型分别来自 `assets/导轮.bbmodel`、`负重轮.bbmodel`、`托带轮.bbmodel`，其中托带轮对应此前“悬挂轮/绕带节点”的角色。
- 使用原始方块元素及旋转变换生成白色网格，包含模型中的非标准角度；以共同轴线对齐 shaft。原始文件不改动。
- 白模用于物品栏和世界中轮子；履带直接引用运行环境的 `create:textures/block/belt.png`，没有复制 Create 材质到新模组。
- 相邻异径轮的内外公切线、独立轮周包覆圆弧、两点细分段与闭环显示。顺序和拓扑在服务端确认并同步。
- Create 导轮动力输入、半轴/全轴连接、轴向透传、固定原型应力消耗。只用履带联动显示其它轮，不通过履带连接额外 Create 动力网络。
- 多个有源导轮目标带速不一致时停止带面联动，扳手可查看冲突。此为明确的原型限制，尚不是离合滑移动力学。比较驱动速度和显示轮转向时计入该轮实际包覆方向，反包覆轮反向旋转。
- 闭合后相对安装点保存节点列表、各轮绕行侧提示与环 UUID，带速和相位同步；成员暂时未加载时停用显示/驱动，已加载但损坏的成员会使环解除。
- 整环状态每游戏刻缓存；悬挂运动与渲染插值仅重建已确认包覆方向的切线，避免运动时重新选择内外绕行。
- 负重轮在 Sable 车体上使用独立盒形碰撞体和单轴弹簧约束，地面反力通过约束传回车体；两端用求解器限位。独立配置自然位置、两端行程、刚度、阻尼、质量与开关。
- 轮心及履带同步位移，显示白色伸缩支杆；同车负重轮相互排除接触。参数、确认后的包覆方向及上次悬挂位置保存，原生句柄重新建立，不写入存档。

## 本轮尚未实现

这是装配与悬挂承载切片，不是完整物理履带。负重轮新增随轮心运动的 Sable 盒形接触，盒体的朝向跟随车体，尚不模拟圆轮滚动；导轮和托带轮仍为固定安装格盒碰撞。带段目前用于几何与渲染，还没有带面 Sable 接触响应或动力推进。

尚未接入：圆轮滚动接触、零导轮自由滚动、带体张力/长度守恒、带面全方向碰撞与承载、炮弹命中/断履、维修材料、其它轮/整条履带的完整参数界面、带面反向驱动 Create、玩家站在带面上的碰撞。不要用该原型判断最终越障能力。

拆分/合并 Sable 车体、蓝图复制、多人与大规模性能尚未实测。首次使用建议新测试世界。既有参考模组可以保留，但不要将新轮与参考模组的轮混接成一个环。

## 验证与构建

`scripts/gradle.ps1 build --offline --console=plain` 编译与打包，`check` 会执行 `geometryTest`、`suspensionTest` 和 `wheelGeometryTest`。几何检查使用独立 Java 主类，不启动 Minecraft，也不需要 JUnit 下载；目前 68 项几何检查覆盖：胶囊形周长/边界、三角形与反向顺序、异径切线、重叠/包含/同心节点、保留交叉顺序、四向反包覆、下侧经过、不合法参数及跨度限制、替代无交叉路径、非相邻段触碰/重叠、正常接点排除和逐点重算的一致性，以及移动轮心、保持包覆方向和重建保存拓扑。另有 35 项悬挂参数检查和 34 项尺寸/布局检查；`python scripts/check_native_suspension.py` 对两个本地 Sable 版本各执行 24 项原生检查，不启动游戏。

构建内存上限调整为 1 GB，工作线程为 1。编译需要的 Create 内嵌 Flywheel/Ponder/Registrate 和 Sable Companion 由 `prepareCompileSupport` 从现有本地 JAR 提取到 build 目录，均不打入产物，不增加运行时重复模组。

模型转换：`python scripts/generate_wheel_assets.py`。生成结果提交于资源目录，普通构建不依赖 Python。源文件哈希、面数和几何尺寸见 `wheel-assets.json`。

产物：`build/libs/trackssimulate-0.4.0-prototype.jar`。隔离 Gradle 测试环境已直接加载项目源码，**不要再把这个 JAR 放进其 mods 文件夹**。本轮没有重新生成 dist 中的旧整合包 ZIP。

渲染接口依据 [NeoForge 1.21.1 BlockEntityRenderer 文档](https://docs.neoforged.net/docs/1.21.1/blockentities/ber/) 及本地 21.1.248 API 核对；具体游戏表现未通过启动验证。

## 装配与预览回归测试

- 五轮内凹布局：先点击左下轮，再点击内侧轮、右下轮和两个上轮；分别选内侧轮上缘/下缘，比较红绿预览与闭合带形。
- 将这一布局在侧视平面旋转 90 度，验证从左/右侧绕行；反包覆轮应与同环其它外包覆轮反向旋转。
- 两个大轮相邻一格安装，几何轮廓重叠时允许闭合；不会再显示“轮体重叠”拒绝信息。
- 选两点后换快捷栏、按 F 交换主副手、打开物品栏、丢物品、右键空气/其它方块，再拿回传送带：旧点与连线不恢复。
- 不切换物品直接潜行点轮，只撤销末点；闭合后存读档，带形和包覆方向保留。
- 选点框黄色 `#FFCB74`、有效预览绿色 `#9EDF73`、交叉/无效预览红色 `#FF7171`，均来自本机 Create 6.0.10 `EjectorTargetHandler` 的目标框/有效和无效轨迹色号；线宽统一为 `1/16` 格，使用 Create/Catnip Outliner。Sable 对这些 Outline 已有坐标变换兼容。
- 点击新增点、潜行撤销、悬停候选轮后，检查整条预览重新规划；颜色只对应目前画出的闭环，不根据轮心连线猜测。
- 用四轮“蝴蝶结”顺序产生无法消除的交叉，检查整条预览变红、选点框仍黄；完成放置后应同时出现红色状态栏提示和聊天提示。

## 0.2.2 规划器边界

交叉检测使用带体中心路径，包含非相邻段相交/接触和共线回折重叠，排除正常相邻段共用的端点。轮体之间重叠本身不等同于带面交叉。圆弧按当前渲染的折线精度检测，未加入带宽/厚度的实体干涉判定。

规划器先求原来的长度/绕行侧候选，再在发现交叉时搜索其他轮包覆方向，并提前剪掉已交叉的部分路径。选点顺序始终不变。为避免大型布置卡住主线程，搜索有确定的状态和比较次数上限；若预算内未找到无交叉解，保留可显示路径并标红，不宣称数学上不存在无交叉解。预览、逐点反馈和最终放置使用同一规划函数。
