# 物理履带设计建议

日期：2026-09-30。状态：设计提案，尚未实现或运行场景测试。本轮未启动游戏。

更新：用户已明确独立模组及两点带段需求。首版架构以 [独立轮组与履带规划](INDEPENDENT_TRACKS_PLAN.md) 为准；下文逐履带板刚体链保留为后续高精度路线和原理分析。

## 结论

建议首版面向金属铰接履带，采用“有质量的独立履带板 + 销轴关节 + 独立轮组 + 张紧机构”，使用简化碰撞几何，并尽量在 Sable 同一个物理世界、同一套接触与约束求解中完成。橡胶连续履带需要另外的弯曲、拉伸和材料模型，不应直接等同于金属链。

两个参考模组都计算实际物理力，并非纯动画；缺失的是履带实体自身的自由度、惯性、闭环连接及由连接产生的受力。给现有动画加若干碰撞盒，只能解决部分阻挡，不足以形成完整履带力学。

## 检查依据

直接检查用户提供的 gearwork-1.0.0.jar、tracks-neoforge-1.21.1-1.0.1.jar，及选定依赖 offroad-1.3.0.jar、sable-2.0.0.jar。使用本机 Vineflower 1.10.1 反编译供分析，输出位于 build/reference-analysis/，未拷贝进新模组源码或打包产物。反编译方法名与调用关系是静态证据，不等于真实运行场景结果。

### Gearwork：同侧履带的分布式等效接触

- TrackPhysicsSubstepSolver.onSubstep / solveBody（52–98 行）：通过 Synaxis 物理子步读取车体与挂接节点，并把计算出的力施加给对应车体。
- solveRun（99–213 行）：把一段履带划分为多个 TrackContactPatch，分配等效质量、计算悬挂承载、纵向滑移、侧向漂移和转向擦地阻力。
- TrackContactSampler.sample（15–43 行）：沿悬挂方向发射多条射线；接触法线与支撑方向点积至少为 0.35。随后拟合等效接触平面。
- addPlanarFrictionForce（215–263 行）：目标表面速度与车体相对地面速度的差产生推进响应；通过质量份额、最大加速度、抓地系数和载荷因子限幅。这是调校后的等效轮地模型，不能等同于逐链节接触的库仑摩擦约束。
- addPreviewForces（286–344 行）：对端部 DRIVE 节点使用前探、抬高的射线产生额外抬升辅助。它处理了越障体验，但不是驱动轮圆周/齿面实际撞上台阶后产生的接触。
- TrackBeltRenderer.renderBelt / renderLocalSegments（24–58 行）：根据相邻安装点绘制平直段、倾斜段、端部包络，使用 UV 滚动表现履带运动。
- 独立轮子也采用 WheelContactSampler + WheelPhysicsSubstepSolver：接触采样、悬挂、目标表面速度和滑移受力，包含驱动、刹车、滚阻和侧向力。

优点：成组求解、地面采样、滑移分解、物理子步和诊断层次清晰。局限：所检查的履带路径没有为每块履带板创建动态刚体或销轴关节；接触主要描述下方支撑，不能自然推导闭环张力、上侧承重、导轮包络碰撞或脱履。

### Tracks：安装点悬挂与驱动冲量

- SableTrackBlockEntity.sable$physicsTick（144–230 行）：根据角色与悬挂启用状态，计算地面距离、弹簧/阻尼、纵向驱动和侧向阻力，累积冲量后施加给所在 Sable 子世界。
- computeMaxExtensionToTerrain（310–350 行）：沿安装点前后布置射线、选择最小延伸量；过滤车体局部向上法线分量低于 0.5 的表面。因此其支撑算法不把陡直墙面视为完整的轮缘接触面。
- isSuspensionActiveForPhysics（755–760 行）：连续悬挂段大于三个时，只有端点和部分交替节点参与该受力计算，其余节点更新视觉伸缩。
- SableTrackRenderer：根据伸缩、相邻高度、角色和调校参数变换轮子/履带片模型，并滚动贴图。
- 普通轮子部分扩展 Offroad WheelMountBlockEntity，通过 mixin 提供偏移与弹簧、驱动、抓地参数；Offroad 1.3.0 的轮子核心也是探地与弹簧/驱动冲量路径。

优点：装配、尺寸、偏移与悬挂调校直观，运行模型较轻。局限：多个支撑安装点并不构成一条有质量且传递销轴力的闭环链；轮间与上侧视觉履带没有对应的独立链节动力学。

限定：以上不表示安装方块或车体完全没有碰撞。普通 VoxelShape 的阻挡，与渲染出来的轮面、端部包络和运行中履带链参与物理，是不同层次。

## 提案的物理组成

| 部件 | 物理表示 | 作用 |
| --- | --- | --- |
| 车体 | Sable 既有动态车体 | 接受轮轴、悬挂和动力机构的反力 |
| 履带板 | 有厚度、宽度、质量、惯量的短刚体 | 与地面、轮组、异物及其它动态结构接触 |
| 销轴 | 相邻履带板之间的旋转关节 | 约束连接处平移、允许绕销轴转动；可设置转角限位 |
| 驱动轮 | 绕轮轴转动的刚体 + 简化齿面/啮合接触 | 接收有限扭矩，通过啮合推动履带 |
| 导向/张紧轮 | 自由转动刚体 + 可滑移轴座 | 改变包络、承受带力，通过轴座控制预紧 |
| 负重轮 | 自由转动刚体 + 悬挂摆臂或滑架 | 车重经轮面传给履带，而非直接传给虚拟地面射线 |
| 托带轮 | 自由转动刚体与轮轴 | 托住上侧履带，允许局部垂落 |
| 张紧机构 | 有预载、行程、刚度、阻尼的滑移机构 | 适应固定节数的闭环，避免强行拉伸履带长度 |

轮子的碰撞形状可用圆柱或低面数凸几何近似；履带板先用盒形。花纹、螺栓等外观细节不要求全部进入碰撞求解。轮缘、导向齿和驱动啮合几何会影响行为，应在需要的功能阶段纳入物理。

所有轮面和履带板都应能在任意姿态接触环境。正常装履带时，轮组主要通过履带与外界间接交互；只有暴露轮面或侧面真正接触障碍时才产生直接轮地接触。不得为了“导轮有物理”而同时给被履带隔开的轮子额外探地支撑，重复承载。

## 必须成立的受力规则

1. **动力入口是驱动轮的有限扭矩。** Create 转速转换为目标转速，但通过有扭矩/功率上限的驱动模型追随；不得直接强制所有链节速度或直接给车体加前进力。Create 应力单位到扭矩的映射需单独定义和标定。
2. **轮地摩擦由接触产生。** 接触求解满足法向冲量非负、切向冲量不超过摩擦界限，例如 `Jn >= 0`、`|Jt| <= mu * Jn`。接触点相对速度要包含两个物体的平移和转动。一般承载接触不应提供吸附力。
3. **反作用力完整。** 电机给轮子的扭矩在车体/轴座上有反扭矩；履带压在另一艘船或可移动平台上时，对双方施加相反的接触冲量。
4. **承载路径连续。** 车体 → 悬挂 → 负重轮 → 履带 → 地面；轮间履带碰上石块时，可以经销轴力与轮面接触传回车体。
5. **固定节数与节距。** 履带环由 N 块、节距 p 的履带板闭合。销轴长度约束不因为可视轮距变大而任意伸长；通过节数选择与张紧轮行程装配。对规则齿距圆，初始节圆半径可按 `r = p / (2*sin(pi/z))` 设计，z 为齿数；实际齿面另做啮合间隙设计。
6. **链节有质量，质量只算一次。** 把材料从车体聚合质量中转成独立物理对象时，要防止双重计重。模型惯量须与碰撞几何及质量一致。
7. **张力是求解结果。** 从关节约束冲量和子步时间估计销轴载荷，而不是配置一个“抓地力”代替张力。金属销轴关节可以传递多方向载荷，不能直接用一根只承拉的无宽度绳子等同替代。
8. **渲染读物理姿态。** 客户端插值服务端链节姿态。初始化几何路径只用于装配，不在每帧把链节投回预设曲线。

## 三条技术路线

| 路线 | 新增能力 | 保留的缺口 | 判断 |
| --- | --- | --- | --- |
| 多方向探测 + 连续包络碰撞 + 一个带速变量 | 改善轮端阻挡、上侧接触、动态平台推力 | 带形若由轮组强制确定，就没有独立弯曲、销轴力和真实脱履 | 可作低成本兼容方案，不能称为完整物理履带 |
| 简化几何的铰接刚体链 | 链节质量、连接受力、上下侧碰撞、张紧、卡滞、轮间承重 | 更小的齿形/胶垫细节被近似，数值稳定性需要调校 | 推荐默认目标 |
| 精细逐齿接触 + 复杂销轴/衬套模型 | 更细的啮合、磨损、弹性和接触压力行为 | 成本与调试量高，实时多人场景须实测 | 作为后续高精度选项 |

推荐路线中，原则上一个物理链节对应一个机械节距。将多片可视板合成一个长刚体会改变弯曲半径、节距和越障能力，不能当作无损性能优化。

## Sable 2.0.0 能力与待验证边界

已在本地发布 JAR 的 Java API 与 Rapier 后端委托路径中确认：

- BoxPhysicsObject 实现 PhysicsPipelineBody，PhysicsPipeline.addBox 可创建独立盒形对象；Rapier 后端将质量、半尺寸与姿态传入 native createBox。
- PhysicsPipeline.addConstraint 的 Rapier 实现接受 PhysicsPipelineBody，并分发 Rotary / Generic / Fixed / Free 配置；不是只能连接两个车体方块集合。
- PhysicsConstraintHandle 暴露 setContactsEnabled、setMotor（含力上限参数）、getJointImpulses、remove、isValid。
- GenericConstraintHandle 有按轴设置限位的接口；旋转关节可用于初步链节连接。

这些证据支持盒形链节和关节的概念验证，不代表完整履带已可直接交付。尚须验证：

- 盒形对象与地形、动态子世界、其它盒形对象的实际碰撞组合、摩擦参数及睡眠/唤醒行为。
- Box 与 SubLevel 混合连接时的锚点坐标语义；源码对 plot-grid 与普通空间有不同校验。
- 圆柱/凸形/复合轮面与齿形碰撞体是否有稳定的公开创建入口。目前检查的公开对象创建入口没有通用凸形工厂，不直接承诺可用。
- 相邻链节禁碰可以通过关节接口表达；非相邻链节、轮缘、车体之间更细的碰撞过滤、CCD、自定义接触能力仍需验证。
- motor target 的实际 native 语义、力上限、关节冲量分量与物理子步时序，不应仅根据 Java 方法名把它当作任意速度电机。
- BoxPhysicsObject 的 Java MassData 使用的惯量表达没有按半尺寸展开；需与 native 实际惯量核对，不能把该 Java 质量视图直接用于精确接触有效质量计算。
- 原生玩家、生物、掉落物未必与这些任意刚体共享同一求解器；承托/碰撞需单独检查和桥接，不能承诺自动获得全部实体交互。
- 区块卸载、保存重载、蓝图复制和客户端同步，不能只依赖一个临时 runtime ID。

如果核心形状/接触能力不足，应通过小范围后端适配或上游扩展解决，并明确支持版本。另开一个独立 Rapier 世界再只给车体回写合力，会把困难转化为双求解器耦合，容易出现时序滞后和能量误差，不是优先路线。

## 数值稳定与运行成本

- 在 Sable 物理子步处理，不以 Minecraft 20 TPS 的游戏逻辑频率直接做显式硬弹簧链；精确子步与迭代配置取决于当前后端，先测再定。
- 链节使用约束连接，不用极大刚度的显式弹簧强行闭环；初始化时满足锚点、闭环与轮面间隙，避免穿透后强行纠正。
- 关闭直接相邻链节之间的碰撞，保留需要的非相邻自碰撞及链节与轮/世界接触；不能把“同一车辆全部不碰撞”作为默认优化。
- 驱动啮合先用简化有效接触几何；保证接触有适度间隙，避免齿面与销轴约束互相冲突。
- 小链节、高轮速、重车体的质量比会增加迭代需求；连续碰撞/扫掠是否可用须确认，不以修改车体质量掩盖问题。
- 物理对象不必各自对应一个 Minecraft Entity 或 SubLevel；装配控制器集中管理，实体身份、存档和渲染批处理另行组织。
- 优先优化接触过滤、复用几何、批量数据访问、渲染实例化、整车睡眠。活动状态下不因摄像机远离就改变履带接触结果。
- 暂不承诺每车链节数、同时车辆数或 TPS；先记录实际 N、接触数、求解耗时、约束误差，再决定预算。

## 建议实施顺序与验收

1. **接口验证台**：几个盒形链节、旋转关节、一块静态地形和一个动态物体。验证双向反力、关节禁碰、锚点坐标、质量、保存/重建，不需要最终美术。
2. **小型闭环台架**：驱动轮、可调张紧轮和闭合链。验证单一扭矩入口、自由轮被动旋转、断电惯性、节距闭合和稳定静置。若轮形 API 缺失，在此阶段解决，不先做漂亮履带动画。
3. **带悬挂车架**：加入负重轮/托带轮、左右双履带；验证上下侧接触、越障和差速转向。
4. **游戏交互**：装配/拆卸、同步、存档、玩家交互、资源替换、Create 动力负载映射。
5. **故障玩法**：轮缘导向与侧向自由度具备后再做脱履；关节载荷有可靠测量后再做断履。不要用随机概率替代对应的力学机制。

关键场景：

| 场景 | 期望行为 |
| --- | --- |
| 两负重轮之间放一块凸起 | 轮间履带受顶，改变形状并向两侧传力，不穿过凸起 |
| 前端包络撞直立台阶 | 先出现水平接触反力；是否爬升取决于几何、摩擦和扭矩，允许失败 |
| 上侧履带放置可碰撞重物 | 局部下垂或压向托带轮，载荷进入张紧与轮组 |
| 轮和履带之间夹入异物 | 出现阻力或卡滞、驱动负载增加；有限动力不能无条件保持带速 |
| 整车架空后驱动 | 履带可循环，车体不能无接触持续平移加速；可出现内部反扭矩姿态响应 |
| 在可移动平台上行驶 | 车辆与平台获得相反接触冲量，而非只推动车辆 |
| 调整张紧行程 | 改变松弛量与销轴载荷，不自动拉伸每片履带板 |
| 侧向碰撞或斜坡 | 有有限侧向接触和滑移；具备真实导向几何后可验证脱履 |
| 保存重载与区块卸载 | 拓扑、张紧状态与质量不重复，卸载时无孤立刚体/关节 |
