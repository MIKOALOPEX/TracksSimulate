# Gearwork 履带炮击损伤改造

2026-09-30，设计与静态代码调查；尚未修改 Gearwork、生成 fork 或运行游戏。

更新：用户已选择制作独立履带，不再等待 Gearwork 源码或推进其 fork。当前实施规划见 [独立轮组与履带规划](INDEPENDENT_TRACKS_PLAN.md)；本文件保留 CBC/Shaolib 查询和损伤调查供独立实现参考。

## 目标

炮弹能够命中 Gearwork 履带的带体，包括轮间直段、上侧和端部包络，而不仅是安装方块。损伤可以切断履带闭环传动，影响驾驶，显示断口，持久保存并支持维修。该能力可先在现有等效履带上实现，随后接入独立刚体链节方案。

## 已确认的代码路径

- CBC AbstractCannonProjectile.clipAndDamage（227 行起）沿当前飞行段先查询方块，截短轨迹，再查实体；具有后续穿透/停止/弹跳处理。
- 同类 onHitEntity（438 行起）有伤害、击退及固定质量扣减逻辑。简单加入一个可受伤实体，并不能自动获得合适的履带材料穿透模型。
- CBC ProjectileDamageHooks.canDamageTerrain 发出的是方块破坏许可事件，不是“在空间中加入任意命中表面”的接口。仅监听该事件无法让原本没有命中的带子被识别。
- CBC 已包含 Sable 坐标变换、命中与冲量相关兼容；新增履带判定必须与其坐标和命中顺序保持一致。
- Shaolib ProjectileHitEvent 携带本地/世界命中点、法线、质量和速度，但现有命中类型为 WORLD_BLOCK / BODY_BLOCK / ENTITY。事后监听事件本身不会创建新的虚拟带体命中，仍需接入其查询/behavior 路径。
- Gearwork TrackPhysicsSubstepSolver.groupRuns 按同轴、相邻坐标组织运行段；TrackBeltRenderer.adjacentTrack 按相邻安装点连接视觉带。若没有独立断裂状态，安装点尚在就可能继续被组为完整履带。

## 建议结构

### 1. 共用履带几何

将当前主要位于渲染端的直段、斜段、包络段构造提取为两端共用的 TrackBeltGeometry。服务器基于权威悬挂状态更新命中形状，客户端按相同定义渲染与插值。

用有厚度的 OBB/凸形分段表示带子。弧段由若干短段近似；不使用覆盖整条履带的一个大 AABB 作为最终命中形状，否则轮间空气也会挡炮弹。区分履带板表面、连接区域、轮子和安装架的损伤目标。

这些初期形状用于弹道判定，不声称它们已经参与 Sable 承重。完整物理链实现后，由链节碰撞几何提供同一命中接口。

### 2. 连续弹道查询

TrackHitQuery 提供飞行段扫掠查询，先用整车包围盒筛选，再对带体做精确检测。考虑弹丸尺寸，不能只检查本 tick 末端位置。移动车辆要处理弹丸与带体相对运动；快速旋转时须用分段/扫掠，不能把两个时刻端点都简单转换到当前车体姿态就视为连续检测。

CBC adapter 把虚拟带体命中与该次迭代中的方块、动态子世界、实体命中合并排序，选择沿剩余飞行段最早的有效命中。穿透后继续剩余轨迹，不能在墙后隔空打断履带，也不能因同时经过原安装方块和虚拟表面重复扣伤害。

Shaolib adapter 接入其运动/查询或弹药 behavior 阶段，不依赖 CBC Entity 基类。两者统一输出 TrackImpact，但不强行把各自的质量、伤害单位当作相同 SI 参数。适配器必须明确换算/标定。

### 3. 材料与断裂

TrackImpact 包含来源、弹丸实例/步骤标识、履带环 ID、命中区域、命中时间比例、世界点/法线及可用弹道信息。TrackDamageResolver 返回损伤、是否断裂，以及交还原弹道系统的穿透/停止/弹跳处理结果。

第一阶段采用可调的材料抗损能力与结构完整度。区分表面损伤与承载连接断裂；不默认任何炮弹擦过都断履，也不要求穿透一个小孔就必然断整条。模型必须注明为游戏内标定，不宣称工程级穿甲预测。

爆炸/破片使用独立适配路径，考虑遮挡、重复事件和多次采样；直接命中、爆炸冲量和伤害不能不加区分地叠加。遵守 CBC 原有破坏限制以及服务器保护策略。

### 4. 持久断履状态

引入稳定的履带环标识、完整度、断口位置、拓扑版本和维修状态。初版的命中段编号是空间几何段，不冒充随履带运动的真实链节编号。未来物理链用独立链节 ID 和销轴连接替换。

建议状态为 INTACT / DAMAGED / SEVERED，JAMMED 为后续独立状态；维修只在明确规则和材料消耗下改变状态，安装点重算、区块重载或拆装邻块不能无条件恢复完整。

服务端唯一判定并修改状态；客户端显示结果。持久化保存拓扑与损伤，不能仅存 Sable 临时运行时 ID。物理线程中的命中/断裂需通过安全队列在允许的阶段修改约束和世界数据。

### 5. 断裂后的受力与显示

- 断裂后，该侧断开的履带环失去连续带传动；不只停止命中位置对应的一个节点。
- 不能直接将整侧所有组件 disabled，因为那会把负重轮、悬挂支撑一并删除。
- 也不能保留完整等效带面上的所有支撑点，否则断掉的跨轮带段仍会悬空承重。过渡模型应改为实际轮子位置的支撑，并明确仍是等效轮地模型。
- 另一侧完整履带继续工作；车辆是否转向、滑行或受阻由剩余驱动与接触决定，不强制清零车速。断带不等同于卡死刹车。
- 断口对应连接在渲染上取消，停止完整闭环滚动。初版可使用断口和垂落的视觉近似，并明确无真实散落链条；物理链阶段则删除被击断销轴约束，让链条动力学自然展开。
- 命中轮子可另外损坏轴承/悬挂，但不是本功能的替代：必须能打到两个安装点之间的带子。

## fork 边界

命中查询、弹药适配、材料损伤应尽量独立，便于以后用于新物理履带。Gearwork 内部主要改动共用几何、环拓扑、驱动/支撑降级、同步与持久化。仅验证可命中的技术原型可以用兼容附属实现；长期同时改悬挂限位、履带拓扑与断裂，完整源码 fork 更适合维护。

目前用户提供的是 JAR，未找到可直接构建的 Gearwork 源码工程。已询问源码路径/仓库；反编译分析输出不是已恢复、可维护的 fork。尚未生成替换原版 Gearwork 的 JAR。

## 最小验收矩阵

1. 从侧面击中两轮之间的直带，记录准确带段命中，不要求命中安装方块。
2. 击中上侧和端部包络能产生损伤；射过轮间空气不误判。
3. 履带前方有墙或装甲时，命中顺序正确；穿透后才处理后方履带。
4. 高速弹丸、旋转/行驶中的车体不明显漏判；同一接触不重复计伤。
5. 断左履带只切断左环驱动，右环继续工作；断口不再形成虚构的连续承重带。
6. 保存、重载和区块卸载后断裂状态保留，维修按规则恢复。
7. CBC 普通弹、机炮弹与 Military Supplement 代表弹种分别测试；Shaolib 弹药单独测试。
8. 再验证爆炸/破片及服务端损伤限制、多人同步与重复事件。

后续编译和静态验证可由助手执行，游戏启动与实测按用户要求由用户自行进行。
