# 0.5.4 物理修正与运行日志

2026-10-04。针对平地跳动、抓取晃动、正面/侧面异常反弹以及纵向和侧向打滑进行修改。**本轮未启动游戏，没有完成上述五项游戏内验收。**

## 确认的错误与修改

- 旧摩擦算法分别求纵向/横向冲量，再按圆形截断，忽略接触点随车体旋转产生的有效质量耦合。在固定种子的 2000 组即时碰撞代数检查中，无驱动输入仍出现总动能变为输入的 1.25694784 倍。新算法使用完整二维有效质量，按摩擦椭圆求解，并限制摩擦更新不得增加动能；同组检查最大比值为 1.0。
- 旧穿透修正可主动制造最高 2 格/秒的分离速度。当前无碰撞恢复弹性，穿透修正速度最多 0.12 格/秒，留出 0.005 格误差容差。这是抑制弹射的修正，深度穿透的恢复效果还需游戏日志判断。
- 连带负重轮不再创建小轮毂刚体及其原生关节。弹簧、阻尼、行程端点改为带面求解器内的有界伸缩坐标，避免接触求解与额外轮毂关节分两次约束车体。接触力仍实际作用于 Sable 车体；未连带的独立负重轮仍使用原来的原生刚体。
- 同一车体所有已登记履带共享车体速度和角速度，交替迭代接触，统一提交冲量，避免左右履带各自完整求解带来的顺序偏差。两个不同车体之间仍由各自车体回调处理，并非整个世界所有约束的统一原生求解器。
- 增加横向摩擦参数，和纵向摩擦共用接触载荷约束；带速使用在接触面上的实际投影，撞墙时不再把带速错误地全部当作沿墙的速度。

连带悬挂现在属于降阶物理近似：轮子的“单轮质量”控制内部伸缩坐标的等效惯性，不再在 Sable 中额外增加这一独立轮体的质量；完整非簧载刚体惯性、履带定长张力尚未实现。此前简化承载试算不能证明重力法杖和原生碰撞下的稳定性，本轮不以它作为游戏通过依据。

## 参数和旧存档

潜行扳手打开轮子设置，再进入“履带”。

- 新轮组默认纵向摩擦 **1.2**，横向摩擦 **1.8**，均可调 0–10。
- 旧存档原纵向摩擦保留；缺少横向字段时取 `max(1.8, 原纵向摩擦)`，防止原先调高抓地的轮组退回很低的侧向值。
- 不需要拆掉重连。旧存档若纵向仍为 0.8，可只将它改为 1.2 或更高再对比，避免恢复全部默认把其他参数也重置。
- 理想 45°平面上静态摩擦平衡至少需要系数 1；这不是“系数达到 1 就保证能爬坡”。实际驱动力、载荷、车体碰撞、是否为台阶近似坡都会影响结果。车越重，现有固定驱动力上限越可能不足，日志将记录质量、驱动力上限和接触滑差以区分原因。

## 日志位置与读取

测试实例自动写入：

`D:\CreateAdd\TracksSimulate\test-environment\combined\logs\trackssimulate-physics.log`

每个文件约 5 MiB，保留当前文件和 `.1`、`.2`、`.3` 三个历史文件，合计约 20 MiB。`.1` 是最近的历史。日志使用 UTF-8，时间戳为 UTC；`tick` 是世界游戏刻，正常每 5 刻一条，每条包含上一窗口的峰值，通常每秒 4 条。速度突变、较深穿透触发 `event=spike`，最多每 2 刻一条；物理保护停用立即写 `event=fault`，并附最近采样。日志写入失败只在 `latest.log` 警告一次，不停用物理。

| 字段 | 含义 |
| --- | --- |
| `vehicle` / `loop` / `root` | 当前运行中的车体标识、持久履带 UUID、控制轮位置，用于区分左右履带和不同车 |
| `mass` / `dt` | Sable 车体质量、物理子步秒数 |
| `com` / `orientation_xyzw` | 世界质心位置和朝向四元数 |
| `native_v_before` / `native_w_before` | 进入本次履带求解前，从原生引擎读取的世界速度（格/秒）和角速度（弧度/秒） |
| `contact_v_after` / `contact_w_after` | 本次履带冲量后的预测速度；**不是稍后原生关节求解完毕的测量值** |
| `contact_J` / `contact_torque_J` | 本子步履带向车体提交的总线冲量、角冲量，世界坐标 |
| `peak_contact_dv` / `peak_contact_dw` | 采样窗口内履带求解造成的最大速度/角速度变化 |
| `peak_external_dv` / `peak_external_dw` | 上一子步履带预测与下一子步原生读数之间的最大变化，包含重力、原生碰撞/约束及其他模组，不能直接归因于法杖 |
| `peak_speed` / `peak_spin` | 窗口内原生读数的最大线速度和角速度，不遗漏两次日志间的峰值 |
| `peak_penetration` | 窗口最大接触穿透深度（格） |
| `mean_contact_force` / `normal_force` | 窗口平均法向接触反力总和 / 某环当前子步反力；为引擎质量单位×格/秒²，不等于始终向上的重量 |
| `speed` / `target` / `driven` / `conflict` | 每环实际带速、原始目标带速、是否驱动、动力是否冲突；目标还受 GUI 的动力限速限制 |
| `mu_long` / `mu_side` / `drive_force_limit` / `brake` | 实际使用的纵/横摩擦、驱动力上限、制动值 |
| `contacts` / `loaded` | 候选接触数 / 法向冲量大于零的接触数；候选包含尚未接触的预测接触 |
| `vertical_contacts` / `wall_contacts` | 承载接触的法向分类；以世界竖直方向分类，并不代表识别了实际地板/墙方块 |
| `max_long_slip` / `max_side_slip` | 有载接触点中最大纵/横向滑差（格/秒） |
| `strongest` | 当前最大法向冲量接触点的位置、法向、穿透及三向冲量，用于定位异常碰撞 |
| `spring` | 每枚连带负重轮的伸长量、向上速度、行程端点、自然位置、刚度、阻尼、等效质量、是否触及端点 |

`event=spike` 是调查触发器，不是自动判定 BUG；正常高速撞击也可能触发。

## 用户实际测试

使用原 BAT 自行启动，保持截图构型，分别观察静置/平地行驶、重力法杖抓取悬空及落地、低速正面撞墙、低速侧碰、45°坡与轻微侧偏。可分别用原重量和加重状态对照。

每种操作保持约 10–20 秒即可，出现弹跳/反弹时记下操作或大致时间。测试后说明哪项仍有问题，助手直接读取本机上述日志及 `latest.log`，无需上传存档或大文件。

本轮自动检查限定为离线编译、接触代数中的被动能量性质、已知 45°单接触摩擦平衡、有界伸缩坐标与日志文件轮转，以及既有路径/参数检查。共 716 项检查通过；没有执行新原生测试场景，也没有启动游戏。上述检查不替代游戏内五项验收。
