# 履带性能架构对齐规划：独立实现与 ARR 边界

日期：2026-10-05。基线：TracksSimulate 0.5.10-prototype；参考对象：用户本机提供的 Gearwork 1.0.0。

状态：**仅规划，未实施优化、未修改运行代码或测试环境、未启动游戏。** 本文是后续独立实现的规格，不是 Gearwork 的移植说明。性能事实引用 [0.5.10 分析](DRIVE_AND_PERFORMANCE_0510.md) 与 [日志统计](analysis/performance-2026-10-05.json)。

## 1. 本次决策

对齐目标是：将每车物理工作组织为批量查询、少量有效接触区域、统一载荷处理和必要的状态同步，使成本随真正发生的接触增长。保留本项目的完整三维带面碰撞、用户点选的异形闭环、内部悬挂和带速自由度。

采用三层表示：

1. **外观层**：模型、贴图、轮子旋转与带面动画，按客户端需要更新。
2. **完整几何层**：有厚度、有宽度的完整带面及其空间查询索引。侧面、上面、下方及未来受弹检测都用这一层。
3. **求解层**：将同一局部接触区域归并成少量约束；把反力、摩擦、悬挂载荷和带速变化统一求解。它可以比几何层稀疏，但不能遗漏实际碰撞面。

这里的“区域”以带面和障碍的实际接触定义，不固定等同于某个轮子，也不固定指向世界下方。不能通过隐藏带面碰撞、只保留负重轮向下射线、降低整车物理频率来满足性能指标。

## 3. 对齐关系

下表中的参考特点来自此前本机调查，仅保留概念层描述；实现不得回到对应反编译文件逐段翻译。

| 参考设计特点 | 本项目独立方案 | 保留的差异 |
|---|---|---|
| 一组接触采样汇总为接触区域 | 从完整带面碰撞候选生成持久接触区域，筛出代表接触点 | 支持侧碰、顶碰、倾斜安装及带宽接触，不限于向下射线。 |
| 批次内复用世界查询上下文 | 同一物理子步的车辆/接触组复用区块、形状和姿态快照 | 形状缓存与世界姿态分离，不能缓存移动障碍的旧位置。 |
| 同车接触按整体载荷处理 | 同车各环共享六自由度车体状态，各环保留带速与驱动，各负重轮保留行程状态 | 不能把十个悬挂轮的独立载荷压成一个固定支撑点。 |
| 有限、可控的物理采样量 | 空间筛选 + 接触区域归并 + 基于误差的重采样 | 不照搬射线数量、采样布局或特殊斜坡补偿参数。 |
| 运行状态与配置分开管理 | 结构版本、运动快照、诊断摘要分别同步 | 不引入 Gearwork/Synaxis/LDLib 作为新的产品依赖；继续基于本项目现有依赖。 |

接触流形、空间包围盒树和距离查询缓存可从公开资料建立独立技术依据，例如 [Box2D 碰撞文档](https://box2d.org/documentation/md_collision.html)。其二维点数和数据结构不直接适用于本项目三维接触，不能原样照搬。

## 4. 数据和更新规则

以下均为本项目提出的职责，不是参考项目的类/API 映射。

| 数据 | 所属范围 / 生命周期 | 更新触发 |
|---|---|---|
| 履带实例身份与结构版本 | 存档、装配体、环实例 | 新建、复制、拆装、销毁。复制须生成独立身份；位置搬移不能被误认成新环或断带。 |
| 有序轮节点、包覆侧、带面局部几何 | 每环 | 连接、轮心形变、尺寸与偏移变化。结构变化与连续形变分别标记，避免每次从头规划。 |
| 车体姿态、速度、质量、惯量、悬挂状态 | 每物理子步快照 | 原生物理步和载荷变化；不能与另一子步的缓存混用。 |
| 地形/车体局部碰撞形状及暴露面 | 有容量上限的区域缓存 | 方块与邻格变化、区块卸载、移动结构拓扑变化；有上下文依赖的形状使用更短生命周期或旁路。 |
| 接触候选与代表点 | 每个物理接触组 | 保守宽阶段筛选后更新；保留障碍身份、接触部位、载荷映射、局部锚点。 |
| 上一步接触冲量 | 持久接触 | 对应关系有效时复用；法向跳变、离开接触、悬挂端点、质量/惯量变化时失效或重算。 |
| GUI/客户端运动快照 | 每环、每轮 | 按同步节奏发布；参数修改及时确认。UI 字符串不在每个物理子步生成。 |

带面段标识应锚定相邻轮节点、弧段/直段类别和参数区间，不能仅使用本帧细分数组下标，否则分段数量变化会错配上一步冲量。

形状缓存只保留局部形状和变更版本，世界坐标变换按当前姿态计算。对暴露面缓存，邻格改变也要失效。所有缓存、诊断队列和历史窗口必须有容量上限及卸载释放路径，避免用更多内存掩盖 CPU 问题。

## 5. 接触区域怎么归并

归并发生在碰撞检测之后、约束求解之前。完整几何层仍回答“是否碰到”；求解层回答“需要哪些独立反力”。

首先按障碍实例、相近法向、空间连续性和悬挂载荷映射划分区域。不能合并不同动态障碍、相反墙面、台阶两侧或不连续的支撑机构。驱动带面的有效运动方向也必须一致；例如反向包覆相邻段不能只因位置接近就混为一组。

区域内优先保留最深位置及接触范围边界，保留足以表达俯仰/侧倾力矩的空间分布。载荷映射必须作用于车体和对应悬挂自由度，不能只保留合力而丢掉力矩、载荷分配或带速耦合。代表点及权重采用非负、可验证的构造；无法满足误差要求时继续细分或恢复原接触集合。

平整路面每环先争取约 8–16 个求解点，这来自本项目约 40 点/环的负载基线与拟定压缩目标，不来自 Gearwork 默认值。它是测量目标，不是所有地形的硬上限。窄梁、阶梯、侧碰、多车夹挤允许增加点数。预算不足必须记录，不能悄悄丢弃支撑。

快速运动区域使用保守扫掠范围；静态或缓变区域可复用接触。射线可以辅助发现可能的地形高度或做便宜的提前筛选，但不能以“射线没有命中”为依据跳过所有侧面碰撞。保守覆盖、悬挂运动及角运动范围须先成立，再谈降低精细查询频率。

## 6. 求解与 Sable 的接入边界

延续本项目的带速自由度、内部悬挂、法向约束和纵横向摩擦，不重新叠加一套独立轮体悬挂约束。驱动倍率放大目标带速，反力仍受当前驱动力与接触压力限制。

同一物理子步内，先收集有效环及候选接触，再按互相作用的车体分组。组内每个车体使用唯一速度/冲量状态，所有相关履带和外部接触共用它，统一提交反作用。没有实际互相作用的车辆不强行放入同一大组。

开发前必须核查当前 Sable 2.0.0+ 可用的物理步边界、回调次序和线程约束。只有保证同子步一致性，才实施跨车体调度；不能用 20 Hz 游戏 tick 的队列假装完成 200 Hz 物理批处理，也不能同时让旧入口和新入口施力。若公共接入点不够，先完成同车批处理、缓存与接触归并，单独报告跨车体接入限制，不能暗中依赖 Gearwork 内部桥接代码。

先保持当前迭代上限，加入约束残差和可行性检查。热启动必须在接触关系稳定、动力学一致性确认后实施。摩擦内部搜索按数值误差停止；减小迭代后仍须满足冲量约束和不额外注入能量的验证。不能用强制速度设定、平移车体或人为抬车越障替代接触物理。

## 7. 分阶段交付

每阶段提供完整可用版本、变更范围、有效自动检查、用户游戏验收项及日志位置。不能以“本轮只验证平地”为由关闭其他接触方向。

| 阶段 | 实施内容 | 出口条件 |
|---|---|---|
| A：基线与实例隔离 | 分阶段计时/计数；统一实例身份；修正复制环与返还登记相互影响；保留现有求解器 | 用户可重现十车场景；日志能按真正实例区分。复制/拆除一辆不影响另一辆，重载不重复返还。 |
| B：等价优化 | 子步查询上下文、形状缓存、缓冲复用；状态字符串/包拆分；有界日志缓冲 | 相同输入下接触集合与响应在数值容差内一致；加载、方块变化和尺寸修改不读到过期数据。日志保留关键物理量。 |
| C：接触区域 | 完整碰撞候选归并为代表约束；保留原精细模式作诊断回退 | 支撑合力/力矩、悬挂载荷、侧面接触及窄支撑有效；平地接触数与求解耗时有实测下降，无无声截断。 |
| D：相互接触车体调度 | 在确认 Sable 接入条件后，共享接触组内状态、避免重复登记并统一施力 | 两车接触等大反向作用，处理顺序不造成明显差异；原生碰撞与模组接触不被算两遍。未满足接口条件时不发布此部分。 |
| E：时间复用与收敛 | 持久接触、热启动、误差控制迭代；最后加入休眠/按误差重采样 | 质量/惯量突变、行程端点、重新接地和快速转向不会沿用错误冲量；驱动、外部碰撞、法杖和载荷改变能及时唤醒。 |

阶段 A 的实例隔离是缓存/持久接触的前置条件，而非性能提速承诺。阶段 B 优先做等价优化，避免一开始就同时更换采样和摩擦模型而无法定位回归。各阶段分别保存可回退版本；精细旧模式只用于有效对照，不能同时执行两套真实施力。

## 8. 测量、配置与验收

诊断摘要每墙钟秒聚合一次，记录模拟步数、墙钟耗时、阶段耗时、车/环/候选/代表点数量、平均和峰值迭代、缓存命中与失效、包大小、日志队列/合并数量。聚合保留最大穿透、速度/角速度、载荷、滑移、质量与质心变化等已有物理量。全量详情只在明确选中的车体或有界异常窗口输出。

性能控制项放入调试棒独立高级页，规划为“标准/精细诊断模式、接触归并误差、重采样误差、统计级别/目标”。默认值由自己的实测决定。引擎步长、物理线程、反弹速度等不是便宜的性能开关；缓存容量和诊断总预算应是服务端统一项，不能由每条履带无限放大。

验收包含：

- 几何/数值自动检查：接触区域边界、合力矩与载荷映射、摩擦耗能、对称性、缓存失效、复制身份及保存恢复；只运行能验证对应逻辑的检查，不把简化夹具当车辆性能证据。
- 用户游戏场景：1/5/10 辆互不接触平地车；十车转向与相撞；45°坡、台阶、窄梁、侧翻、水平/三角带环、三条以上履带；非固定重物、重力法杖；装配/拆解/复制/重载。
- 对照固定输入、质量、几何、视距、依赖版本、驱动倍率与日志级别；Gearwork 使用用户本机安装作行为和成本参考，注明两者碰撞能力差异。
- 十车目标：总体稳定 20 TPS、tick 耗时 p95 ≤ 50 ms；履带部分争取 10–15 ms/tick。改善的量化依据是同场景耗时和功能验收，不承诺预先指定的提速倍数。
- 可选 JFR 由用户实际测试时采集，限制单次时长和文件大小，建议单文件上限 128 MB；不用长时间无限录制。助手不主动启动游戏，不下载或上传大型文件。

CBC 断履尚未实现。本轮规划保留完整几何查询与损伤接口，不能把“留了接口”写成炮弹交互已经通过测试。
