# 独立轮组与履带：可行性和实施规划

2026-09-30。状态：设计提案与静态接口核查，尚未实现本文件中的功能，也未启动游戏。本文件依据用户最新六点要求，作为后续讨论基线；暂不要求用户回答问题。

本方案取代 `PHYSICAL_TRACK_DESIGN.md` 中“首版即逐履带板刚体链”的推荐，并取代 `GEARWORK_CBC_DAMAGE_PLAN.md` 中修改 Gearwork 的实施路线。两份旧文档保留为原理和弹药接口调查资料。

## 1. 推荐路线和边界

独立实现 Tracks Simulate，最小依赖为 Create + Sable。采用**有序轮组路径、两点带段碰撞、少量悬挂和带体自由度、服务端统一损伤**。不要求安装 Gearwork、Tracks 或 Bits 'n' Tracks。

这条路线比每块履带板都建立刚体和销轴约束更适合首版，也满足带子可支撑、可碰撞、可被炮弹击断的要求。但它仍是简化力学模型：不会自然具备逐链节翻折、缠绕、散落和所有脱履行为。后续可以在相同拓扑、材料和损伤接口下替换为更细的物理模型。

首版的关键不是“画出更多碰撞盒”，而是接触力如何传到带体、轮子、悬挂和车体。若只给固定路径挂上碰撞盒，履带会成为刚性梁，无法正确体现松弛、张力和悬挂运动。

### 按最新要求采用的工作解释

| 用户名称 | 功能 | 本方案中的物理行为 |
| --- | --- | --- |
| 导轮 | 路径节点、动力输入、半轴/全轴 | 固定轮心；轮体有碰撞；可设自由转动/接合驱动；全轴沿轴向传递 Create 动力 |
| 悬挂轮 | 仅作为包围线路径节点，过轮形式待完善 | 暂按固定轮心的绕带轮处理，没有独立弹簧悬挂或主动驱动力；预留包覆侧和路径规则 |
| 负重轮 | 轮地支撑与悬挂 | 安装点固定，轮心沿悬挂行程移动；移动轮体有独立碰撞，具有弹簧、阻尼和两端限位 |
| 履带带体 | 各轮之间的连续带面 | 带面接触、支撑、纵横向摩擦、张力传递、炮击损伤和断裂 |

“只有负重轮提供支撑”解释为：**只有负重轮拥有专门的弹簧悬挂承载机构**。导轮、悬挂轮和带体仍有真实接触反力；例如导轮撞台阶时可能得到向上反力。若禁止这些竖向反力，就无法同时满足其实体碰撞要求。这里明确解释，不改名、不擅自把悬挂轮当成负重轮。

首版约束为同一 Sable 车体内、平行轮轴、同一履带平面的闭环；支持三角形、多边形及可解的内凹路径。静态世界允许装配和配置，但固定在世界上的结构不会因为施力变成可驾驶车体。跨车体履带、空间扭转带另列扩展项。左右两侧是独立履带环。

## 3. 玩家装配流程

### 3.1 在 shaft 上安装轮子

使用三种轮子物品之一右键普通 Create shaft，服务端将其替换成对应轮组方块。保留轴向、水浸等适用状态；同时完成物品消耗、轮组数据建立和 Create 动力网络更新，失败则不消耗。不得只替换模型而留下旧轴的重复碰撞或旧动力节点。

轮组方块是固定安装座。轮心位置、半径、轴向偏移及负重轮悬挂位移保存为独立数据。负重轮上下移动时，Create 网络仍连接固定安装座；不能通过每帧移动方块来模拟悬挂。轮子占用一个安装方块位置，并不意味着几何只能占一格。

导轮半轴只在选定的一侧提供轴连接，全轴两侧均连接并透传动力。轮子自身的“与履带接合”状态和“轴是否透传”分别保存：断履不应切断一根仍完好的贯通轴。不同左右履带的动力分离仍由玩家的轴、离合器和传动布置决定。

负重轮与悬挂轮暂不作为主动驱动节点；轴向安装接口是否允许额外透传，留为后续功能决定，不在首版自动扩展。

### 3.2 用原版 Create 传送带物品选择轮组

只在点击本模组轮组或已有本模组选择会话时接管交互；普通 shaft 之间仍执行 Create 原有传送带逻辑。Create 6.0.10 的 `BeltConnectorItem` 原生是首轴/次轴连接，不能直接存多轮有序闭环。

拟定交互：第一次点选开始，逐轮追加，最后再次点击首轮闭合。显示序号、方向箭头、带宽和包覆预览。撤销末点/清空选择提供操作入口，具体快捷键后续再定。选择会话保存维度、车体稳定标识、节点标识和顺序，服务端验证距离、权限和节点是否仍存在。材料消耗在成功闭合时结算；按长度还是按环消耗暂不定死。

**保持玩家顺序，不按坐标排序，不改成凸包，不静默删除内侧轮。** 对可计算但机械上错误的绕带，保留其选择意图，标示交叉/干涉并使其卡滞或无法接合。对重合轮心、无实数切线、非法数值、跨维度、过量节点等不可求解/越界输入，报告原因并不提交工作闭环；“玩家承担错误”不等于允许求解器出现 NaN 或无限耗时。

初期不提供真正的带体自碰撞动力学：错误交叉可以进入明确的 JAMMED 状态。不能显示正常穿过自身并继续无损传动，或为了避免交叉而偷偷重新排序。

### 3.3 过轮几何

相邻两轮根据轮心、包覆半径和所选包覆侧计算切点；切点之间为自由带段，轮面上为圆弧段。三角形自然由三组切线和包角形成，不需要预设梯形。接入悬挂轮时保留内侧/外侧绕行规则接口，避免日后重写存档。

选中、实际接触、动力接合是三个不同状态。选中的轮不能被静默删掉；当实际路径不能接触它时应反馈异常或待调整。反向包覆会改变轮转向与带速的符号，不能全环套一个同号转速。

偏移参数必须满足所属环平面约束；多轮宽度可以不同，但需有实际的轴向重叠接触区域。调大轮半径/改偏移会改变整环路径和张紧量，不能只改客户端模型。

## 4. 两点判定带段的具体含义

这里的“判定块”是物理/命中代理，不是不断放置和删除的 Minecraft 世界方块，也不默认使用大量隐形实体。

每个直带小段以 A、B 两点定义中心线，另有带宽、厚度和轴向，形成定向盒 OBB。AABB 仅作快速空间筛选，精确命中使用定向盒或等效薄棱柱。圆弧按误差界限分成短段，较长自由跨度可插入少量形变节点，每两个相邻节点仍形成一段判定体。

带段数量由路径长度、曲率、地形和允许误差确定，**不随贴图履带板数量增长**。改变画质不能改变支撑力或可被击中的面积。盒段接缝需要受控覆盖并合并重复接触，避免缝隙漏弹和重叠处双倍受力。

一份服务端几何状态供以下系统使用：带面碰撞、轮体碰撞、炮弹查询、爆炸查询、选择高亮、客户端渲染。碰撞前使用预测位置，求解后发布校正状态；渲染可以插值，伤害不能使用客户端视觉插值结果。

不能把整环围成的大包围盒当实体，否则轮间空气也会挡炮弹。包围盒只负责筛选，之后逐段精确检测。

### 跨度为何还需要张力与形变

两个端点间的直带不能无条件像钢梁一样托住车体。首版至少需要以下规则：

- 带体只承受拉力，不作为可承压的刚杆；低张力和松弛会改变其可传递载荷。
- 自由跨度保留有限横向形变能力：少量中间节点或等价形变自由度，承受带体重力、端点拉力和地形接触约束。
- 接触点推起带面时，变化的带长/张力通过轮面传回车体和负重轮悬挂。不能直接把接触点吸附到地面后免费抬升车体。
- 对长跨度、低张力、复杂地形超出当前形变容量的情况，限制工作范围并显示超限；不得把无法模拟的松垂跨度当作完全刚性支撑。

两个节点定义的是局部判定段；这不要求整个轮间跨度永远只有一块直盒。初次验证可仅使用短而绷紧的跨度，正式功能再加入受控松弛，避免首个原型承担所有软体问题。

## 5. 受力模型与轮体碰撞

### 5.1 必须保存的状态

每个负重轮保存悬挂位移 q、速度 qdot；整环保存带速 u、材料相位 s、自然长度 L0 和损伤；张力及形变节点保存必要动态量。轮子的转动惯量和带体质量要纳入动力响应，不能仅让动画跟随车速。

轮心定义为 `安装点 + 可配置偏移 + 悬挂方向 × q`，最后由 Sable 车体姿态变换到世界坐标。负重轮的可视模型、实体碰撞和炮击位置都使用同一个轮心。固定支架保留自身碰撞，移动轮体的旧位置不留下隐形障碍。

轮体粗筛使用包围盒，精测优先采用简化圆柱/圆盘或少量凸形近似；若技术验证阶段只能用盒，明确它是碰撞原型，不能把盒角卡台阶的表现当作最终车轮性能。

### 5.2 悬挂硬限位

定义 q 沿伸长方向增大，要求 `q_min <= q <= q_max`。

- q_min：最短长度，最大压缩后的硬位置。
- q_max：最长长度，无载伸长的硬位置。
- q0：弹簧自然长度，可结合预载调整静态姿态。
- k、c：弹簧刚度和阻尼；两端可以有渐进缓冲，但缓冲不替代硬限位。

达到限位时必须处理向外的速度与约束反力；简单 clamp 显示位置不构成物理硬限位。自然长度可以与最长长度不同，无载时也不一定自动达到最长长度，取决于预载、轮重、阻尼及其它约束。

Gearwork 所查 `restTravel`、目标压缩比例和弹簧强度适合调车高/软硬，但不应作为两个独立的物理止挡参数来复刻。新系统应直接提供用户之前要求的两端位置。

### 5.3 接触与力的传递

接触应支持底面、侧面、正面、上面，不再只沿车体向下射线。对地形方块的碰撞形状和其它 Sable 车体进行粗筛与精测；轮体位移大或车体速度高时使用扫掠/自适应子步控制穿透。

接触法向冲量不能吸引分离中的物体，切向摩擦由法向载荷限制。纵向/横向可采用不同摩擦系数，但需要联合限幅，避免两方向各取得完整摩擦预算。传动扭矩和接触载荷共同决定可用驱动力，悬空时不得得到无限抓地。

带面地形反力经带体张力、轮面接触、负重轮悬挂/固定轮轴承传给车体；直接轮地接触也进入同一求解。应使用接触几何对应的约束关系/Jacobian 分配广义冲量，不能给每一个带段都分配一份完整车重。增加细分段数后，整车承载结果应收敛而非成倍增加。

同一接触对只能由一条路径施加法向与摩擦响应。若轮体使用 Sable 原生接触，就不能再叠加旧式射线弹簧去支撑同一块地面；若本模组负责移动几何，则原生安装方块中应只保留支架实际形状。轮与带重合区域也需接触去重，不能把它们当成互不相关的两层承重面。

与另一个动态车体接触时，必须向双方施加大小相等、方向相反的冲量，并计入接触点角速度；只读取对方速度而不施加反作用力是不完整的。车体、轮体、带体质量不能在代理刚体和宿主质量里重复计算。

### 5.4 无导轮和多个动力源

无导轮是合法环：所有轮都可由带体接触带动，带速由接触摩擦、等效惯量、轴承阻力和制动共同决定。车体被外力拖动时履带滚动；离地时允许惯性续转，逐渐因阻力减速。不能用车体线速度直接覆盖带速，否则无法表现打滑、空转和制动。

接合导轮的理想带速由 `u = 包覆方向符号 × 角速度 × 有效半径` 给出。Create RPM 是目标运动输入，真实响应由有限扭矩/离合器控制，并映射到 Create 应力消耗；Create 应力单位与物理扭矩之间要独立标定，不能宣称原生能量守恒。

同一环多个导轮若给出不同目标带速，必须表现为离合滑移、争驱或卡滞并受扭矩上限约束，不能简单平均转速创造免费动力。第一版不把自由滚动自动转成 Create 发电/动力源；轴向透传与带体反向驱动 Create 网络是不同功能，后者另行设计。

## 6. Sable 2.0.0 的接口证据与技术门槛

已核查本地 2.0.0 公共 API 与 Rapier 后端 Java 调用，未运行物理实验。

| 已见能力 | 能支持的规划 | 尚不能据此承诺的内容 |
| --- | --- | --- |
| `BlockEntitySubLevelActor.sable$physicsTick`、物理子步事件 | 同步轮组更新到 Sable 物理子步 | 自动与原生全部接触约束联合迭代 |
| `RigidBodyHandle`、`PhysicsPipeline.applyImpulse` | 施加接触点冲量、车体反力与转矩 | 只施加一次合力即可获得稳定软体/关节效果 |
| `BoxPhysicsObject`、`PhysicsPipeline.addBox` | 有质量盒体，适合小规模碰撞验证 | 公共 API 已提供任意圆柱、复合体、运动学带面速度 |
| Generic / Rotary 约束、`setLimit`、带力限制的 motor | 轮座和悬挂限位试验 | 已验证所有所需轴向、坐标系、不同质量比都稳定 |
| `BlockSubLevelDynamicCollider.buildBoxes`、`VoxelColliderData.addBox/clearBoxes` | API 声明存在 | 每个 BlockEntity 的跨格动态形状已经能安全逐子步更新 |

**具体限制：** 所查 `RapierVoxelColliderBakery` 按 BlockState 缓存几何，并将普通形状的每个盒裁到局部 0..1。普通 `getCollisionShape` 不能直接表示超出安装格的大轮、跨轮带段或各个实例不同的悬挂位置。在所查 Java 调用链中没有确认可直接使用的逐实例动态更新入口；不能仅看到 DynamicCollider 名称就判定问题已解决。

`BoxPhysicsObject` Java 侧惯量也需与 native 侧核对：所见质量追踪器使用 mass/6 的简化惯量，而盒子尺寸可变。精确物理前必须验证或在适配层修正，不能凭接口形状推断它已给出正确惯量。

### 优先验证的两条实现通路

1. **公共 API 原型：** 使用小盒体和原生关节，验证负重轮单自由度行程、接触反力、生命周期和限位。它用于验证连接车体的能力，不直接作为最终圆轮或逐段“传送盒”实现。
2. **推荐主路线：** 独立移动几何查询 + 简化轮/带约束求解，在 Sable 同一物理子步内交换冲量。对高速碰撞、多个动态车体以及原生车体接触并存的稳定性设技术闸门；需要时通过隔离的 Sable 适配层接入后端接触/形状能力，而不是大范围侵入业务代码。

如果公共 API 的耦合精度不足，后端适配或小范围 Sable 扩展将成为必要工作。这是本项目最主要的技术风险，不能承诺只写几个方块类即可完成。禁止每帧 teleport 一排动态盒来冒充可变形履带：这会绕过速度和反作用力，容易注入能量。

原生物理物体与 Minecraft 玩家/普通实体的碰撞不是自动等价关系。选择命中、炮弹查询、玩家站立/阻挡需要各自接入同一几何索引，并分别验收。首版至少覆盖地形、其它车体和炮弹；“所有轮有碰撞”是否包括全部原版实体交互必须在交付说明中逐项标记，不能用其中一项代替全部。

## 7. 建议开放的参数

配置分轮子、整环和服务器三层。普通界面使用预设和少量常用项，高级界面开放工程参数。物理量统一游戏长度单位与秒；质量/力/扭矩采用明确标定的物理单位体系，不能混用 Create 应力值。默认数值待原型实测确定，不在当前纸面阶段假装已经调好。

| 层级/对象 | 参数 | 含义与约束 |
| --- | --- | --- |
| 全部轮子 | 有效半径、宽度 | 决定包覆路径、碰撞和旋转关系；可视半径只允许有限模型修正 |
| 全部轮子 | 轴向、前后、上下安装偏移 | 改变真实轮心；受同平面与接触重叠校验约束 |
| 全部轮子 | 包覆侧、允许包角/绕行模式 | 解决内外包覆与悬挂轮过轮；保持玩家节点顺序 |
| 全部轮子 | 轮体质量、转动惯量、轴承阻力 | 优先由尺寸/材质推导，高级参数受服务器限制 |
| 全部轮子 | 轮/带接触材质、显示样式 | 外观不单独改变服务端物理；隐藏模型不能隐藏碰撞 |
| 导轮 | 半轴/全轴、连接侧 | 决定 Create 轴向连接和透传 |
| 导轮 | 驱动接合、离合状态 | 脱开后可自由滚动；轴透传独立 |
| 导轮 | 方向、最大传递扭矩、响应强度 | 带速由 RPM 与半径决定，扭矩限制加速能力 |
| 导轮 | 制动强度/红石控制 | 与驱动分开；制动不得超过受限扭矩与接触抓地能力 |
| 负重轮 | 悬挂方向、q_min、q_max | 最短/最长硬位置，不是仅渲染裁剪 |
| 负重轮 | 自然长度 q0、预载/目标静态下沉量 | q0/预载为求解参数；目标下沉量是自动配弹簧的调参入口，避免三者互相矛盾 |
| 负重轮 | 弹簧刚度、压缩阻尼、回弹阻尼 | 可由承载质量份额、频率/阻尼比推导；高级模式才直接修改 |
| 负重轮 | 压缩/伸长缓冲区、渐进刚度 | 接近两端软缓冲，终点仍是硬限制 |
| 负重轮 | 承载权重、轮胎/轮缘接触材质 | 用于调参分配，不能额外创造车体质量或承载力 |
| 悬挂轮 | 包覆规则、位置、尺寸、轴承阻力 | 暂不提供主动驱动和负重轮弹簧参数 |
| 履带环 | 带宽、厚度、节距、材料预设 | 决定判定截面、材质、质量和可视链节间距 |
| 履带环 | 自然长度/链节数量、预紧量 | 指定一种主输入，其余派生，避免相互矛盾 |
| 履带环 | 拉伸刚度、阻尼、最大允许张力 | 约束松紧、能量耗散和过载失效；首版可先只记录过载 |
| 履带环 | 纵向静/动摩擦、横向摩擦、滚动损耗 | 由材质预设主导；不能以任意大“抓地”掩盖求解错误 |
| 履带环 | 单位长度质量、等效转动惯量 | 质量不能按碰撞细分重复累计 |
| 履带环 | 完整度、连接强度、抗损参数、维修成本 | 服务端游戏材质标定；不宣称真实工程穿甲计算 |
| 客户端 | 颜色、纹理、链节视觉密度、调试显示 | 不改变物理细分、损伤和动力 |
| 服务器 | 轮数/带段数/总长度/同时活动环上限 | 控制最坏开销；数值随测量确定 |
| 服务器 | 接触容差、求解迭代预算、扫掠精度 | 不作为玩家增加抓地或承载的旋钮 |

建议常用界面只先显示半径、宽度、三向偏移、包覆侧、两端行程、车高、软硬/阻尼预设、半轴/全轴、驱动/制动和张紧。暂不加入 Gearwork 的预探测抬升系数作为核心承载设置；先用真实前缘接触解决越障。

## 8. 炮击断履与持久损伤

从第一个版本就定义 `TrackLoopId`、轮节点稳定 ID、拓扑版本、材料坐标和断口状态。**空间判定段 ID 与实际随带移动的材料区间分开**：否则受伤位置会永远固定在车体前端，或者调整碰撞细分就把损伤洗掉。闭环滚动通过材料相位映射损伤，断裂后取消完整环的周期映射。

炮弹使用上一位置到下一位置的扫掠查询，结合车体在本时间步的运动；候选包括带段、轮体及原弹道系统的方块/实体，并按命中时间排序。炮弹先撞装甲或墙，再穿透到履带，不能隔墙扣履带血。高速和旋转车体需要扫掠，只有当前帧 AABB 不够。

CBC 适配要接入其分段碰撞/穿透处理，不只监听爆炸或地形破坏事件。原 CBC 对实体命中有自己的质量扣减，不能用大量隐形实体就假定薄履带的穿透已经正确。命中结果交回原系统，保留穿透、弹跳、停止和引信行为，并去重同一步多段重叠命中。

CBC 与使用 Shaolib 的弹药分别适配；统一内部 TrackImpact，但不假设它们共用 projectile Entity 或相同伤害单位。爆炸和破片另有范围、遮挡和重复伤害处理。未安装战斗模组时独立履带仍能正常加载。

断裂至少产生以下结果：

1. 破坏连续传动路径，停止完整环共同传速和预紧；另一侧完好环不受直接影响。
2. 删除不存在的跨口承重，重新计算有效带段；首版开放带模拟不成熟时，明确退化为轮子接触承载，不能保留悬空断带支撑。
3. 负重轮本体及悬挂继续工作；不把整侧轮子一起禁用，不强制清零车速。
4. 显示断口/松落状态，持久保存损伤；维修按材料和规则恢复，重载区块或重算路径不自动修好。

完全松落链条的散落碰撞列为后续阶段。若首版只用垂落视觉近似，必须明确标注，而不让它继续承担隐藏的物理支撑。

## 9. 模块、依赖和兼容策略

建议模块边界（规划名称，尚未创建实现）：

| 模块 | 职责 |
| --- | --- |
| WheelMount / WheelConfig | 三类安装座、配置、轴向动力接口 |
| TrackSelection / TrackTopology | 原带物品交互、有序闭环、稳定标识 |
| TrackGeometry | 切线/圆弧、移动轮心、两点段、材料坐标 |
| TrackDynamics | 悬挂、张力、带速、接触和驱动约束 |
| SableBridge | 子步、姿态、冲量、原生物体/后端能力差异 |
| TrackCollisionIndex | 带面/轮体空间索引、扫掠与精确命中 |
| TrackDamage / CombatAdapters | 损伤持久化，CBC/Shaolib 可选适配 |
| TrackSync / Renderer | 服务端状态同步、客户端插值与外观 |

每个物理子步只由车体/履带管理器集中处理整环一次，不能由每个轮子的回调重复求解整条履带。网络同步以环拓扑版本、配置和紧凑动态状态为主，不逐帧逐段发送全部盒体。区块卸载、车体拆分/合并、维度变化时必须销毁/重建代理和连接，不能继续引用旧 native 句柄。

| 依赖 | 当前建议 |
| --- | --- |
| Minecraft / Java / NeoForge | 保持现有 1.21.1 / 21 / 21.1.248 基础工程；加载范围沿用当前记录 |
| Create | 当前 `[6.0.10,6.1.0)`，本机 6.0.10；Flywheel/Ponder 使用相匹配的内置依赖 |
| Sable | 继续声明 `[2.0.0,)`；编译最低 2.0.0，测试 2.0.0 与常规 2.0.5 |
| Gearwork / Tracks / Synaxis / Offroad | 参考环境保留，新模组不因参考这些设计而添加必需依赖 |
| Bits 'n' Tracks CE / Bits 'n' Bobs | 只研究设计，不作为首版必需运行依赖 |
| LDLib2 | UI 工具候选，核心物理不依赖；没有必要时使用 Create/NeoForge 现有 UI 能力 |

Sable 开放为 2.0.0+ 是用户要求的加载策略，不是未来版本全部兼容的证明。公共 API 尽量按最低版本编译；若必须调用后端内部实现，用能力检测和明确适配版本区分。新版本不支持所需能力时给出可诊断错误，不在未验证的 native 接口上继续运行。不能为适应参考 CE 就直接把最低版本提到 2.0.3。

现有 base / base-2.0.0 用于独立功能验证，gearwork / tracks / combined 用于参考比较；战斗测试以后另建隔离配置。现有 BAT、代理读取和联网失败后离线准备逻辑本轮保持原样，仍由用户自行启动。

## 10. 实施顺序与可检查的验收

| 阶段 | 工作产物 | 验收门槛 |
| --- | --- | --- |
| P0：物理能力验证 | 单个移动轮体、单根受载带段、SableBridge 原型 | 两端硬限位、偏移轮碰撞、侧面碰撞、动态对方反力；确认 2.0.0/2.0.5 接口和质量/惯量；失败先调整适配路线 |
| P1：装配与拓扑 | 三种 shaft 转换、原带多选、几何预览、存档 | 顺序不变，三角形与零导轮可建，普通 Create 带不受影响，非法输入不崩溃 |
| P2：轮组和传动 | 真悬挂状态、半轴/全轴、有限扭矩驱动、自由带速 | 负重轮位置和碰撞一致，无导轮拖动滚带，离地无凭空推进，多动力源冲突可控 |
| P3：带面承载 | 全方向两点段碰撞、张力和有限形变、接触去重 | 轮间石块能托带，侧墙/前阶能接触，松带不等同钢梁；改变细分密度不会加倍承载 |
| P4：断履战斗适配 | 材料损伤、CBC 接入、断口与维修 | 直段/上段/轮周可命中，轮间空气不挡弹，遮挡/穿透正确，断履不删轮支撑，存读档损伤保留 |
| P5：扩展和性能 | 完善悬挂轮过带、其它弹药、多人/实体交互、限额 | 车体拆分/卸载无残留，玩家交互明确，多环性能有数据，支持范围公开 |

各阶段可以交付小型可测功能，但 P1/P2 原型不能宣称已经完成用户要求的整套物理履带。运行场景由用户通过测试脚本启动，助手准备编译、日志开关和测试说明。

第一批场景：悬空自由伸长、重载压到底、静止斜坡、轮间孤立石块、导轮撞前阶、上侧撞横梁、车体倾倒后的侧接触、两辆动态车互碰、零导轮拖行、两导轮反向驱动、两种细分密度对比、运动中射击上下带段、断履重载存档。性能至少记录活动环/段/接触数和物理子步耗时，不提前承诺 FPS/TPS 或车辆数量。
